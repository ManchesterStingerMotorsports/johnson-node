# Johnson Node

Johnson Node is a modular CAN node for sensor networks. It is designed as a small configurable board that can sit on a CAN bus, read local sensors or IO, and publish data for the rest of the network to use.

At its simplest, it is an ADC and IO node on CAN. A lot of the ESP32-S3 IO is broken out to a 14-pin multipin connector, so the same base board can be adapted for different sensor, control, and interface jobs without spinning a whole new main node each time.

The board can also interface with add-on hats. This repo currently includes hat hardware for:

- GPS and IMU
- Strain gauge interface

## Project Status

This project is still in active development. The firmware in `main/` is useful as a starting point and currently contains early CAN/TWAI support code, but it should not be treated as the finished application or final API yet.

The hardware is the main source of truth for the intended system shape: a configurable ESP32-S3 CAN node with exposed IO and hat expansion.

## Hardware Overview

The base board is built around an ESP32-S3 module and CAN bus interface. Its role is to provide:

- CAN connectivity for distributed sensor networks.
- Local ADC and IO handling.
- A 14-pin multipin connector exposing a broad set of IO.
- Expansion through application-specific hats.
- A reusable base for different sensor-node configurations.

The main board uses CAN bus nets named `CANH`, `CANL`, `CAND`, and `CANR`.

Some footprints and 3D models are referenced from custom KiCad libraries. If KiCad opens a project with missing symbols, footprints, or models, check that the required custom libraries are installed and mapped on your machine.

## Firmware

The firmware is an ESP-IDF C++ project targeting `esp32s3`. At the moment it contains early CAN helper code using ESP-IDF's TWAI driver, plus an example `app_main()`.

The current firmware is mainly there to bring up and exercise CAN behaviour while the project evolves. Expect the application structure, CAN message definitions, and IO handling to change.

Basic build flow:

```powershell
idf.py set-target esp32s3
idf.py build
```

Flash and monitor, replacing `COMx` with the board's serial port:

```powershell
idf.py -p COMx flash monitor
```

## Intended Use

Johnson Node is intended for CAN-based sensor networks where small, configurable nodes collect data close to the source and report it back over the bus. Example uses include:

- Reading analogue sensors and publishing ADC values over CAN.
- Bridging dedicated sensor hats onto the main CAN network.
- Building reusable IO nodes for test rigs, vehicles, robots, or distributed instrumentation.
- Prototyping new sensor interfaces using the exposed 14-pin connector.

## Development Notes

- `build/` is generated by ESP-IDF and should not be edited by hand.
- `sdkconfig` is committed so target and flash settings are reproducible.
- The top-level CMake file enables `MINIMAL_BUILD`, so new ESP-IDF component dependencies should be added explicitly in `main/CMakeLists.txt`.
